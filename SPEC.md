# compostmodernism.org — Implementation Spec

## Overview

A blog built with SvelteKit (Node adapter) hosted on a personal VPS. Posts are stored
in SQLite and published via iOS Shortcuts. The app runs in Docker, with Caddy handling
routing and automatic TLS as part of an existing gateway setup.

Posts support three modes inspired by Daring Fireball:
- **Link post** — has a URL and title; the title links externally
- **Titled post** — has a title but no URL; title is a heading
- **Plain post** — body text only, no title or URL

All posts have autogenerated datestamp permalinks and support tags, browsable at
`/tag/[slug]`. Posts are editable via a minimal password-protected `/admin` page.

Images are uploaded via a dedicated Shortcut or the admin page, processed server-side
with sharp (EXIF stripped, resized, converted to WebP), and stored in Cloudflare R2.
R2 also receives nightly SQLite database backups. Posts are additionally exported nightly
to individual markdown files with YAML frontmatter and committed to the git archive.

## 2. Slug Generation

### `src/lib/slug.js`

Slugs are generated at insert time and stored permanently. They never change, even if
the post title is later edited.

```javascript
import { createHash } from 'crypto';

/**
 * Converts a title string into a URL-safe slug.
 * "Hello, World!" → "hello-world"
 */
export function slugify(title) {
  return title
    .toLowerCase()
    .trim()
    .replace(/[^\w\s-]/g, '')
    .replace(/[\s_]+/g, '-')
    .replace(/^-+|-+$/g, '');
}

/**
 * Generates a short hash for untitled posts.
 * Based on the current timestamp so it's deterministic at insert time.
 */
export function hashSlug(timestamp) {
  return createHash('md5')
    .update(String(timestamp))
    .digest('hex')
    .slice(0, 8);
}

/**
 * Formats a timestamp into datestamp parts.
 * 1719792000000 → { year: '2024', month: '07', day: '01' }
 */
export function dateParts(timestamp) {
  const d = new Date(timestamp);
  return {
    year:  String(d.getUTCFullYear()),
    month: String(d.getUTCMonth() + 1).padStart(2, '0'),
    day:   String(d.getUTCDate()).padStart(2, '0')
  };
}

/**
 * Assembles a full permalink path from a post row.
 * e.g. /2024/07/01/hello-world or /2024/07/01/p8a3f4b2
 */
export function permalink(post) {
  const { year, month, day } = dateParts(post.created_at);
  return `/${year}/${month}/${day}/${post.slug}`;
}
```

## 3. SQLite Layer

The DB layer has three pieces: **versioned schema files** under `migrations/`,
a **migration runner** at `src/lib/migrate.ts`, and a **query factory** at
`src/lib/db.ts`. Schema changes are append-only — never edit a committed
migration; add a new numbered file. The runner applies pending files
inside per-file transactions and tracks state via SQLite's built-in
`PRAGMA user_version`.

### `migrations/`

Each file is `NNN_short_description.sql` (e.g. `001_init.sql`,
`002_add_image_dimensions.sql`). `001_init.sql` is the baseline — it uses
`CREATE TABLE IF NOT EXISTS` so existing databases bootstrap cleanly (the
live `posts.db` was migrated this way; `user_version` went 0 → 1 with no
data loss).

The current baseline creates `posts`, `tags`, `post_tags`, `images`, and
`post_images` plus unique indexes on slug and image key columns.

**Schema notes:**
- `slug` on posts — autogenerated at insert time, stored permanently, never recomputed
- `title` — optional on all post types
- `url` — optional; its presence marks a post as a link post
- A post with a `url` must also have a `title` (enforced in the endpoint)
- `tags` — one row per unique tag; `name` is display text, `slug` is URL-safe
- `post_tags` — join table; cascades deletes so removing a post cleans up its tag rows
- `images` — append-only ledger of R2 keys; `post_images` join table maps body URLs to ledger rows (see §15)

### `src/lib/migrate.ts`

Reads `PRAGMA user_version`, filters files in `migrations/` matching
`^\d{3}_.+\.sql$`, sorts by numeric prefix, and applies each pending file
in its own transaction. Failed migrations roll back atomically — including
the `user_version` bump — so the runner can be safely retried.

### `scripts/init-db.ts`

Run once on the VPS for first-time bootstrap. The script is now a thin
wrapper around `createDb()`, which itself invokes `migrate()`:

```typescript
import { join } from 'node:path';
import { createDb } from '../src/lib/db';

const db = createDb(join(process.cwd(), 'posts.db'));
db.raw.close();
```

Run with: `npx tsx scripts/init-db.ts`. In production, container restart
also runs migrations via the SvelteKit server's own `createDb()` call —
so this script is only needed for first-time DB creation or manual ops.

### `src/lib/db.ts`

A factory `createDb(path)` opens a connection, sets `journal_mode = WAL`
(except for `:memory:` test DBs), enables `foreign_keys = ON`, and calls
`migrate(raw)`. The factory returns query functions plus the raw `Database`
handle. A `defaultDb()` singleton (used by the SvelteKit server) opens
`./posts.db` lazily and is re-exported as named functions so endpoints can
`import { insertPost } from '$lib/db'` directly.

The query layer below is the reference shape. The actual implementation in
the repo is TypeScript with `PostRow` / `Post` / `Tag` / `ImageRow`
interfaces — see `src/lib/db.ts` for the typed version.

```javascript
import Database from 'better-sqlite3';
import { join } from 'path';
import { slugify, hashSlug } from '$lib/slug.js';

const db = new Database(join(process.cwd(), 'posts.db'));
db.pragma('journal_mode = WAL');
db.pragma('foreign_keys = ON');

function uniqueSlug(candidate) {
  let slug = candidate;
  let suffix = 2;
  while (db.prepare('SELECT 1 FROM posts WHERE slug = ?').get(slug)) {
    slug = `${candidate}-${suffix++}`;
  }
  return slug;
}

/**
 * Looks up each tag name, inserting it if it doesn't exist, and returns tag ids.
 * Tags are normalised: "Food & Drink" → slug "food-drink".
 */
function resolveTagIds(tagNames = []) {
  return tagNames.map(name => {
    const slug = slugify(name);
    const existing = db.prepare('SELECT id FROM tags WHERE slug = ?').get(slug);
    if (existing) return existing.id;
    return db.prepare('INSERT INTO tags (name, slug) VALUES (?, ?)').run(name.trim(), slug).lastInsertRowid;
  });
}

/**
 * Fetches tag names for a given post id.
 */
function getTagsForPost(postId) {
  return db.prepare(`
    SELECT t.name, t.slug FROM tags t
    JOIN post_tags pt ON pt.tag_id = t.id
    WHERE pt.post_id = ?
    ORDER BY t.name
  `).all(postId).map(t => ({ name: t.name, slug: t.slug }));
}

/**
 * Replaces all tags for a post. Used by both insert and update paths.
 */
function setPostTags(postId, tagNames = []) {
  db.prepare('DELETE FROM post_tags WHERE post_id = ?').run(postId);
  const tagIds = resolveTagIds(tagNames);
  const insert = db.prepare('INSERT OR IGNORE INTO post_tags (post_id, tag_id) VALUES (?, ?)');
  for (const tagId of tagIds) insert.run(postId, tagId);
}

function hydrate(post) {
  return {
    ...post,
    type: 'post',
    date: post.created_at,
    tags: getTagsForPost(post.id)
  };
}

export function getPosts({ limit = 50 } = {}) {
  return db
    .prepare('SELECT * FROM posts ORDER BY created_at DESC LIMIT ?')
    .all(limit)
    .map(hydrate);
}

export function getPostBySlug(slug) {
  const post = db.prepare('SELECT * FROM posts WHERE slug = ?').get(slug);
  return post ? hydrate(post) : null;
}

export function getPostsByTag(tagSlug, { limit = 50 } = {}) {
  return db.prepare(`
    SELECT p.* FROM posts p
    JOIN post_tags pt ON pt.post_id = p.id
    JOIN tags t ON t.id = pt.tag_id
    WHERE t.slug = ?
    ORDER BY p.created_at DESC
    LIMIT ?
  `).all(tagSlug, limit).map(hydrate);
}

export function getAllTags() {
  return db.prepare(`
    SELECT t.name, t.slug, COUNT(pt.post_id) as count
    FROM tags t
    JOIN post_tags pt ON pt.tag_id = t.id
    GROUP BY t.id
    ORDER BY count DESC
  `).all();
}

export function insertPost({ body, title = null, url = null, tags = [] }) {
  const now = Date.now();
  const baseSlug = title ? slugify(title) : hashSlug(now);
  const slug = uniqueSlug(baseSlug);

  const result = db
    .prepare(`
      INSERT INTO posts (slug, body, title, url, created_at)
      VALUES (?, ?, ?, ?, ?)
    `)
    .run(slug, body, title, url, now);

  setPostTags(result.lastInsertRowid, tags);
  return result;
}

export function updatePost(slug, { body, title, url, tags }) {
  db.prepare(`
    UPDATE posts SET body = ?, title = ?, url = ? WHERE slug = ?
  `).run(body, title ?? null, url ?? null, slug);

  if (Array.isArray(tags)) {
    const post = db.prepare('SELECT id FROM posts WHERE slug = ?').get(slug);
    setPostTags(post.id, tags);
  }
}
```

## 4. Cloudflare R2

R2 is used for two purposes: serving images and storing nightly database backups. Both
live in a single bucket (`compostmodernism`) under separate key prefixes:

```
compostmodernism/
  images/2026/07/01/a3b4c5d6.webp
  backups/posts-2026-07-01.db
```

### R2 setup (one-time, in Cloudflare dashboard)

1. Create a bucket named `compostmodernism`
2. Under **Public access**, enable the R2 public bucket URL, or attach a custom subdomain
   (`static.compostmodernism.org`) via a CNAME in your Cloudflare DNS settings pointing
   to the bucket's `r2.dev` URL
3. Create an **API token** with Object Read & Write permissions scoped to this bucket
4. Note your **Account ID**, **Access Key ID**, and **Secret Access Key**

The public base URL for static files (images and backups) will be either:
- `https://pub-XXXX.r2.dev` (default R2 URL), or
- `https://static.compostmodernism.org` (custom subdomain — recommended)

Set `R2_PUBLIC_URL` in PM2 env to whichever you use.

### `src/lib/r2.js`

```javascript
import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3';
import { env } from '$env/dynamic/private';

export const r2 = new S3Client({
  region: 'auto',
  endpoint: `https://${env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId: env.R2_ACCESS_KEY_ID,
    secretAccessKey: env.R2_SECRET_ACCESS_KEY
  }
});

/**
 * Uploads a buffer to R2 and returns the public URL.
 *
 * @param {string} key      - e.g. "images/2026/07/01/a3b4c5d6.webp"
 * @param {Buffer} buffer   - processed image bytes
 * @param {string} mimeType - e.g. "image/webp"
 */
export async function uploadToR2(key, buffer, mimeType) {
  await r2.send(new PutObjectCommand({
    Bucket: env.R2_BUCKET,
    Key: key,
    Body: buffer,
    ContentType: mimeType
  }));

  return `${env.R2_PUBLIC_URL}/${key}`;
}
```

## 7. API Endpoints

### `src/routes/api/post/+server.js` — Create post

```javascript
import { json } from '@sveltejs/kit';
import { insertPost } from '$lib/db.js';
import { permalink } from '$lib/slug.js';
import { env } from '$env/dynamic/private';

export async function POST({ request }) {
  const auth = request.headers.get('Authorization');
  if (!env.POST_SECRET || auth !== `Bearer ${env.POST_SECRET}`) {
    return json({ error: 'Unauthorized' }, { status: 401 });
  }

  const { body, title, url, tags } = await request.json();

  if (!body?.trim()) {
    return json({ error: 'body is required' }, { status: 400 });
  }
  if (url?.trim() && !title?.trim()) {
    return json({ error: 'title is required when url is provided' }, { status: 400 });
  }

  const result = insertPost({
    body: body.trim(),
    title: title?.trim() || null,
    url: url?.trim() || null,
    tags: Array.isArray(tags) ? tags.filter(Boolean) : []
  });

  const post = { slug: result.lastInsertRowid, created_at: Date.now() };
  return json({ ok: true, permalink: permalink(post) }, { status: 201 });
}
```

### `src/routes/api/post/[slug]/+server.js` — Edit post

```javascript
import { json } from '@sveltejs/kit';
import { getPostBySlug, updatePost } from '$lib/db.js';
import { env } from '$env/dynamic/private';

export async function PATCH({ request, params }) {
  const auth = request.headers.get('Authorization');
  if (!env.POST_SECRET || auth !== `Bearer ${env.POST_SECRET}`) {
    return json({ error: 'Unauthorized' }, { status: 401 });
  }

  const post = getPostBySlug(params.slug);
  if (!post) return json({ error: 'Not found' }, { status: 404 });

  const updates = await request.json();
  const body  = updates.body?.trim()  ?? post.body;
  const title = updates.title?.trim() || null;
  const url   = updates.url?.trim()   || null;
  const tags  = Array.isArray(updates.tags) ? updates.tags.filter(Boolean) : undefined;

  if (url && !title) {
    return json({ error: 'title is required when url is provided' }, { status: 400 });
  }

  updatePost(params.slug, { body, title, url, tags });
  return json({ ok: true });
}
```

### `src/routes/api/upload/+server.js` — Upload image

Accepts a multipart form upload, runs the sharp pipeline, writes to R2, and returns
the public URL. All processing happens server-side; the client sends a raw image file.

**Sharp pipeline (in order):**
1. Strip all EXIF metadata — removes GPS coordinates and device info
2. Resize to max 1600px on the long edge, preserving aspect ratio
3. Convert to WebP at quality 82

**Naming scheme:** `images/YYYY/MM/DD/<8-char-timestamp-hash>.webp`
Organised by upload date, collision-resistant, no user-supplied filenames in the path.

```javascript
import { json } from '@sveltejs/kit';
import sharp from 'sharp';
import { createHash } from 'crypto';
import { uploadToR2 } from '$lib/r2.js';
import { env } from '$env/dynamic/private';

export async function POST({ request }) {
  const auth = request.headers.get('Authorization');
  if (!env.POST_SECRET || auth !== `Bearer ${env.POST_SECRET}`) {
    return json({ error: 'Unauthorized' }, { status: 401 });
  }

  const formData = await request.formData();
  const file = formData.get('image');

  if (!file || typeof file === 'string') {
    return json({ error: 'image file is required' }, { status: 400 });
  }

  const inputBuffer = Buffer.from(await file.arrayBuffer());

  // sharp pipeline: strip EXIF → resize → WebP
  const outputBuffer = await sharp(inputBuffer)
    .rotate()                          // honour EXIF orientation before stripping
    .resize(1600, 1600, {
      fit: 'inside',                   // preserve aspect ratio, never upscale
      withoutEnlargement: true
    })
    .withMetadata(false)               // strip all EXIF
    .webp({ quality: 82 })
    .toBuffer();

  const now = Date.now();
  const hash = createHash('md5').update(String(now)).digest('hex').slice(0, 8);
  const d = new Date(now);
  const year  = d.getUTCFullYear();
  const month = String(d.getUTCMonth() + 1).padStart(2, '0');
  const day   = String(d.getUTCDate()).padStart(2, '0');
  const key   = `images/${year}/${month}/${day}/${hash}.webp`;

  const url = await uploadToR2(key, outputBuffer, 'image/webp');

  return json({ ok: true, url }, { status: 201 });
}
```

## 9. Docker Configuration

### `Dockerfile`

Two-stage build. The builder installs the native-deps toolchain
(`python3 make g++ vips-dev` for `better-sqlite3` and `sharp`), runs
`npm ci`, builds the SvelteKit bundle, then prunes to production deps.
The runtime stage copies `node_modules/`, `build/`, `migrations/`,
`scripts/`, `src/`, plus `package.json` and `tsconfig.json` — no
toolchain ships.

The build runs on the VPS during `docker compose up -d --build`. CI's
build job is a gate (it verifies the build + tests pass before SSH'ing
to the VPS), not a packaging step.

```dockerfile
FROM node:20-alpine AS builder
WORKDIR /app
RUN apk add --no-cache python3 make g++ vips-dev
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build && npm prune --omit=dev

FROM node:20-alpine AS runtime
WORKDIR /app
RUN apk add --no-cache vips
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/build ./build
COPY package.json package-lock.json tsconfig.json ./
COPY src/ ./src/
COPY scripts/ ./scripts/
COPY migrations/ ./migrations/
ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "build/index.js"]
```

`COPY migrations/` is required — the server runs `migrate()` on startup
and the runner throws if the directory is absent. New migrations apply
in this order: push code → CI build job passes → SSH into VPS →
`git pull && docker compose up -d --build` → server boot calls
`createDb()` → `migrate()` finds files past `user_version` and applies
them inside transactions before the first request lands.

`src/` ships into the runtime image because the standalone scripts
(`init-db.ts`, `export-and-backup.ts`) import `../src/lib/db.ts` via
relative paths and run under `tsx` in production. The SvelteKit server
itself reads only `build/`; the duplication is ~50 KB and the alternative
(compiling scripts ahead of time) adds a build step for two files run
rarely.

### `docker-compose.yml`

The app joins an external `web` network that the Caddy gateway also
belongs to — Caddy reaches the app by `container_name` over that
network, so no host ports are published.

```yaml
services:
  app:
    build: .
    container_name: compostmodernism
    restart: unless-stopped
    env_file: .env
    volumes:
      - ./posts.db:/app/posts.db
    networks:
      - web

networks:
  web:
    external: true
```

The `web` network is owned by the gateway (`~/gateway/docker-compose.yml`).
This compose file just joins it. If `docker compose up` errors with
"network web not found", start the gateway first.

## 10. Caddy Configuration

The Caddy gateway (`~/gateway`) is a single Caddy container that imports
per-site Caddyfiles via volume mounts. Each site lives in its own
directory with a `Caddyfile`; the gateway mounts that file into
`/etc/caddy/sites/<domain>.caddy`. Caddy hot-reloads when files change.

### `Caddyfile` (in this repo, mounted into the gateway)

```
compostmodernism.org {
    reverse_proxy compostmodernism:3000

    request_body {
        max_size 20MB
    }
}
```

`reverse_proxy compostmodernism:3000` — Caddy and the app share the
`web` docker network, so Caddy resolves the app by its `container_name`.
No host port is involved.

`max_size 20MB` is required — without it Caddy rejects large image
uploads before they reach SvelteKit.

### One-time mount in the gateway

Add to `~/gateway/docker-compose.yml`:

```yaml
services:
  caddy:
    volumes:
      - ~/sites/compostmodernism.org/Caddyfile:/etc/caddy/sites/compostmodernism.org.caddy:ro
```

Then bounce the gateway: `cd ~/gateway && docker-compose up -d`. Caddy
picks up the new file automatically.

## 11. GitHub Actions Deployment

Two jobs: **build** verifies a clean checkout type-checks, tests, and
builds; **deploy** SSHes to the VPS and triggers `git pull` +
`docker compose up -d --build`. The VPS holds the canonical source via
a long-lived git checkout under `~/sites/compostmodernism.org`.

The trigger branch is `blog-engine` during initial bring-up; switch to
`main` once the deploy mechanics are proven.

### `.github/workflows/deploy.yml`

```yaml
name: Deploy

on:
  push:
    branches: [blog-engine]

jobs:
  build:
    name: Build & test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm run check
      - run: npm test
      - run: npm run build

  deploy:
    name: Deploy to VPS
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key: ${{ secrets.VPS_SSH_KEY }}
          script: |
            set -euo pipefail
            cd ~/sites/compostmodernism.org
            git fetch origin
            git checkout blog-engine
            git pull --ff-only
            docker compose up -d --build
```

### Required GitHub Secrets

| Secret | Value |
|---|---|
| `VPS_HOST` | Your VPS IP or hostname (or SSH config alias resolved to one) |
| `VPS_USER` | SSH user on the VPS |
| `VPS_SSH_KEY` | Private SSH key — generate a dedicated, passphraseless ed25519 key scoped to deploys (do **not** reuse a personal key) |

The corresponding public key on the VPS should be added to
`~/.ssh/authorized_keys` with restrictions:

```
no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty ssh-ed25519 AAAA... gha-deploy@compostmodernism
```

These options block the key from being repurposed for tunneling or
shell sessions if the GHA secret ever leaks — it can still execute the
`script:` block, which is all `appleboy/ssh-action` needs.

## 13. Nightly Export and Backup

A single script runs two jobs: it exports each post to its own dated markdown file with
YAML frontmatter, commits any new or changed files to git, then uploads a binary snapshot
of `posts.db` to R2.

**Archive file format:** `archive/YYYY/MM/DD/slug.md`

Re-running the script overwrites existing files in place. If a post was edited since the
last run, the updated file appears in the git diff — a clean audit trail of changes.

### `scripts/export-and-backup.ts`

The actual implementation is TypeScript and lives in this repo at
`scripts/export-and-backup.ts`. The structure below is the reference
shape — see the real file for typed Post/Tag wiring, the testable
helper split (`renderFrontmatter`, `archivePath`, `backupKey`,
`backupDatabase`), and the `import.meta`-guarded CLI entry. The script
runs under `tsx` in production.

```javascript
import Database from 'better-sqlite3';
import { readFileSync, writeFileSync, mkdirSync } from 'fs';
import { join } from 'path';
import { execSync } from 'child_process';
import { S3Client, PutObjectCommand } from '@aws-sdk/client-s3';
import { permalink, dateParts } from '../src/lib/slug.js';

const DB_PATH = join(process.cwd(), 'posts.db');
const db = new Database(DB_PATH);

// ── 1. Per-post markdown export → git ────────────────────────────────────────

const posts = db.prepare('SELECT * FROM posts ORDER BY created_at ASC').all();

for (const post of posts) {
  const tags = db.prepare(`
    SELECT t.name FROM tags t
    JOIN post_tags pt ON pt.tag_id = t.id
    WHERE pt.post_id = ?
    ORDER BY t.name
  `).all(post.id).map(t => t.name);

  const { year, month, day } = dateParts(post.created_at);
  const dir  = join('archive', year, month, day);
  const path = join(dir, `${post.slug}.md`);

  // Build YAML frontmatter
  const meta = [
    '---',
    `id: ${post.id}`,
    `slug: ${post.slug}`,
    `created_at: ${new Date(post.created_at).toISOString()}`,
    `permalink: https://compostmodernism.org${permalink(post)}`,
  ];

  if (post.title) meta.push(`title: ${JSON.stringify(post.title)}`);
  if (post.url)   meta.push(`url: ${post.url}`);
  if (tags.length) {
    meta.push('tags:');
    tags.forEach(t => meta.push(`  - ${t}`));
  }

  meta.push('---', '', post.body, '');

  mkdirSync(dir, { recursive: true });
  writeFileSync(path, meta.join('\n'), 'utf8');
}

console.log(`Exported ${posts.length} posts to archive/`);

try {
  execSync('git add archive/');
  execSync(`git commit -m "chore: export posts ${new Date().toISOString().slice(0, 10)}"`);
  execSync('git push');
  console.log('Pushed archive to git');
} catch {
  console.log('No git changes to commit');
}

// ── 2. Binary DB backup → R2 ─────────────────────────────────────────────────

db.close(); // flush WAL before reading the file

const r2 = new S3Client({
  region: 'auto',
  endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId:     process.env.R2_ACCESS_KEY_ID,
    secretAccessKey: process.env.R2_SECRET_ACCESS_KEY
  }
});

const date   = new Date().toISOString().slice(0, 10);
const key    = `backups/posts-${date}.db`;
const buffer = readFileSync(DB_PATH);

await r2.send(new PutObjectCommand({
  Bucket:      process.env.R2_BUCKET,
  Key:         key,
  Body:        buffer,
  ContentType: 'application/octet-stream'
}));

console.log(`Uploaded DB backup to R2: ${key}`);
```

### Cron

The cron job runs inside the container so it has access to `.env` variables:

```
0 3 * * * docker exec compostmodernism npx tsx scripts/export-and-backup.ts >> /var/log/compostmodernism-backup.log 2>&1
```

R2 backups accumulate daily. Set a **lifecycle rule** in the Cloudflare dashboard to
expire objects under the `backups/` prefix after 90 days.

## 15. Image Ledger

A minimal record of every image uploaded to R2, plus a join table linking posts to
the images they reference. The ledger lets you keep a notebook of uploaded assets
(with editable title/alt/caption/credit) and answers "which posts use this image?"
without scanning every post body.

The ledger is descriptive, not authoritative: R2 is the source of truth for whether
an object exists. The DB just remembers the things you've put there and lets you
annotate them.

### Schema (now part of `migrations/001_init.sql`)

The ledger tables are included in the baseline migration. The DDL:

```sql
CREATE TABLE IF NOT EXISTS images (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  key         TEXT    NOT NULL UNIQUE,   -- R2 object key, e.g. images/2026/05/13/abc12345.webp
  uploaded_at INTEGER NOT NULL,
  title       TEXT,
  alt         TEXT,
  caption     TEXT,
  credit      TEXT
);

CREATE TABLE IF NOT EXISTS post_images (
  post_id  INTEGER NOT NULL REFERENCES posts(id)  ON DELETE CASCADE,
  image_id INTEGER NOT NULL REFERENCES images(id) ON DELETE CASCADE,
  PRIMARY KEY (post_id, image_id)
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_images_key ON images (key);
```

**Notes:**
- The public URL is intentionally **not** stored. It is derived as
  `${R2_PUBLIC_URL}/${key}` at read time so a future URL change is a config edit,
  not a migration.
- File metadata (mime, bytes, width, height) is **not** stored. The upload pipeline
  guarantees `image/webp`, max 1600px long edge — these facts are derivable.
- `ON DELETE CASCADE` on `post_images` cleans join rows when a post is deleted.
  Image rows themselves persist; orphans in R2 are cheap and recoverable.

### New functions in `src/lib/db.ts`

```typescript
import { env } from '$env/dynamic/private';

export interface ImageRow {
  id: number;
  key: string;
  uploaded_at: number;
  title: string | null;
  alt: string | null;
  caption: string | null;
  credit: string | null;
}

/**
 * Records an uploaded image in the ledger. Idempotent on key.
 */
export function recordImage(key: string): ImageRow {
  const now = Date.now();
  db.prepare(`
    INSERT INTO images (key, uploaded_at) VALUES (?, ?)
    ON CONFLICT (key) DO NOTHING
  `).run(key, now);
  return db.prepare('SELECT * FROM images WHERE key = ?').get(key) as ImageRow;
}

/**
 * Scans a post body for R2 image URLs, looks up their ledger rows, and replaces
 * the post_images join rows for the post. Unknown URLs are silently skipped.
 */
export function setPostImages(postId: number, body: string): void {
  db.prepare('DELETE FROM post_images WHERE post_id = ?').run(postId);

  const prefix = env.R2_PUBLIC_URL.replace(/\/$/, '') + '/';
  const keys = new Set<string>();
  // Match the prefix followed by an images/... path up to the .webp extension.
  const pattern = new RegExp(
    prefix.replace(/[.*+?^${}()|[\]\\]/g, '\\$&') + '(images/[^\\s)"\'<>]+\\.webp)',
    'g'
  );
  for (const match of body.matchAll(pattern)) keys.add(match[1]);

  if (!keys.size) return;
  const select = db.prepare('SELECT id FROM images WHERE key = ?');
  const insert = db.prepare('INSERT OR IGNORE INTO post_images (post_id, image_id) VALUES (?, ?)');
  for (const key of keys) {
    const row = select.get(key) as { id: number } | undefined;
    if (row) insert.run(postId, row.id);
  }
}
```

`insertPost` and `updatePost` each call `setPostImages(postId, body)` after writing
the post row — the same shape as the existing `setPostTags` call.

### Endpoint change

In `src/routes/api/upload/+server.ts`, after a successful `uploadToR2` call, also
call `recordImage(key)`. The response shape is unchanged; the ledger insert is a
side-effect.

### What this does **not** do

- No admin UI for editing image metadata. The columns exist; populating them is a
  future add-on (or hand-edit via `sqlite3 posts.db`).
- No image picker / reuse UI. The ledger makes reuse *possible* later; the initial
  build only records what's been uploaded and which posts cite it.
- No stub rows for manually pasted URLs that don't match a ledger entry. Only
  uploads through `/api/upload` create rows.

1. Navigate to `compostmodernism.org/admin`, sign in

### Add-on C — RSS Feed

Adds a standard RSS 2.0 feed at `/feed.xml` for readers and feed aggregators.

**No new dependencies required** — XML can be built as a plain string.

**New file: `src/routes/feed.xml/+server.js`**
```javascript
import { getPosts } from '$lib/db.js';
import { permalink } from '$lib/slug.js';

export async function GET() {
  const posts = getPosts({ limit: 20 });

  const items = posts.map(post => {
    const url = `https://compostmodernism.org${permalink(post)}`;
    const title = post.title ?? post.body.slice(0, 60);
    const date = new Date(post.created_at).toUTCString();

    return `
      <item>
        <title><![CDATA[${title}]]></title>
        <link>${url}</link>
        <guid>${url}</guid>
        <pubDate>${date}</pubDate>
        <description><![CDATA[${post.body}]]></description>
      </item>`;
  }).join('\n');

  const xml = `<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>compostmodernism.org</title>
    <link>https://compostmodernism.org</link>
    <description>Recent posts</description>
    ${items}
  </channel>
</rss>`;

  return new Response(xml, {
    headers: { 'Content-Type': 'application/rss+xml' }
  });
}
```

Add a `<link>` tag in `+layout.svelte` so feed readers auto-discover it:
```html
<link rel="alternate" type="application/rss+xml" href="/feed.xml" title="compostmodernism.org" />
```

If essays (Add-on A) are also active, merge them into the feed sorted by date.

### Add-on D — Full-text Search

Adds a `/search` page backed by SQLite FTS5 (Full-Text Search), a built-in SQLite
extension that tokenises post content and supports fast ranked queries. Significantly
better than `LIKE` for anything beyond the smallest archives — handles partial words,
ranks by relevance, and stays fast as post count grows.

**No new dependencies required** — FTS5 is bundled with SQLite and exposed via
`better-sqlite3`.

#### Schema addition

Add to `scripts/init-db.js` after the existing table definitions:

```javascript
db.exec(`
  CREATE VIRTUAL TABLE IF NOT EXISTS posts_fts USING fts5(
    slug UNINDEXED,
    title,
    body,
    content='posts',
    content_rowid='id'
  );

  -- Keep FTS index in sync with posts table
  CREATE TRIGGER IF NOT EXISTS posts_ai AFTER INSERT ON posts BEGIN
    INSERT INTO posts_fts(rowid, slug, title, body)
    VALUES (new.id, new.slug, new.title, new.body);
  END;

  CREATE TRIGGER IF NOT EXISTS posts_au AFTER UPDATE ON posts BEGIN
    INSERT INTO posts_fts(posts_fts, rowid, slug, title, body)
    VALUES ('delete', old.id, old.slug, old.title, old.body);
    INSERT INTO posts_fts(rowid, slug, title, body)
    VALUES (new.id, new.slug, new.title, new.body);
  END;

  CREATE TRIGGER IF NOT EXISTS posts_ad AFTER DELETE ON posts BEGIN
    INSERT INTO posts_fts(posts_fts, rowid, slug, title, body)
    VALUES ('delete', old.id, old.slug, old.title, old.body);
  END;
`);
```

The triggers keep `posts_fts` in sync automatically — no changes needed to the insert
or update functions in `db.js`.

#### New function in `src/lib/db.js`

```javascript
export function searchPosts(query, { limit = 30 } = {}) {
  if (!query?.trim()) return [];
  return db.prepare(`
    SELECT p.* FROM posts p
    JOIN posts_fts ON posts_fts.rowid = p.id
    WHERE posts_fts MATCH ?
    ORDER BY rank
    LIMIT ?
  `).all(query.trim(), limit).map(hydrate);
}
```

#### New route: `src/routes/search/+page.server.js`

```javascript
import { searchPosts } from '$lib/db.js';
import { permalink } from '$lib/slug.js';

export async function load({ url }) {
  const q = url.searchParams.get('q') ?? '';
  const results = q ? searchPosts(q) : [];

  return {
    q,
    results: results.map(p => ({ ...p, permalink: permalink(p) }))
  };
}
```

#### New route: `src/routes/search/+page.svelte`

```svelte
    <!-- same post template as index page -->
  {/each}
</main>
```

#### Populating the FTS index for existing posts

If posts already exist in the database when FTS is added, backfill the index:

```javascript
db.exec(`
  INSERT INTO posts_fts(rowid, slug, title, body)
  SELECT id, slug, title, body FROM posts;
`);
```

Run this once as a one-off script or add it to `init-db.js` behind an existence check.

a one-step Shortcut that asks for a query and opens
`https://compostmodernism.org/search?q=[query]` in Safari.
